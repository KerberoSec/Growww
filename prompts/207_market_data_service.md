# 207 - Real-Time Market Data & WebSocket Streaming Service (Go)

## Purpose
The Real-Time Market Data & WebSocket Streaming Service is the high-bandwidth distribution nerve center of Growww. It ingests high-frequency trade execution streams, raw order book updates, and Level-2 depth diffs from the Rust matching engine, synthesizes real-time market tickers and OHLCV (Open, High, Low, Close, Volume) candlestick bars, and broadcasts sub-second price updates to hundreds of thousands of concurrent Flutter mobile, desktop, and Next.js web trading clients over persistent WebSockets.

In Growww's asset-backed fractional equity ecosystem, transparent and instantaneous price discovery is essential. Investors must see accurate, real-time prices down to hundredths of a paisa and fractional volume depth before executing fractional share transactions.

## What You Are Building
A massively concurrent Go streaming service (`services/market-data-service`). Concrete deliverables include:
- High-concurrency WebSocket server managing 100,000+ simultaneous client connections with minimal memory footprint (<25KB per idle connection).
- Channel multiplexer supporting granular client subscriptions (e.g. `subscribe:ticker:INE002A01018`, `subscribe:depth:INE002A01018:20`, `subscribe:trades:INE002A01018`).
- Real-time in-memory candlestick aggregator generating multi-timeframe OHLCV bars (1m, 5m, 15m, 1h, 1d) with rolling window buffers.
- Redis Pub/Sub integration for horizontal multi-node fan-out clustering.
- Kafka consumer group ingesting `matching.trades.v1` and `matching.depth.v1`.
- gRPC server providing fast historical candlestick and snapshot data for mobile and web charting components (TradingView Lightweight Charts).

## Scope Boundaries
- **In Scope:**
 - WebSocket connection lifecycle (upgrade, ping-pong heartbeats, reconnects, token auth).
 - L2 order book depth aggregation (top 5, 10, 20 price levels).
 - Ticker aggregation (LTP, 24h high/low/volume, absolute and percentage daily change).
 - In-memory OHLCV candle construction and TimescaleDB / ClickHouse archival.
 - Slow consumer detection and backpressure management (ring buffers with head-dropping).
- **Out of Scope / Handled Elsewhere:**
 - Order matching and execution generation (Prompt 205).
 - Client-side chart rendering in Flutter (Prompt 508) or Web (Prompt 603).
 - Master securities metadata management (Prompt 407).
 - Settlement orchestration (Prompt 208).

## Technology to Use
- **Primary Language & Framework:** Go 1.22+. Go is uniquely suited for high-concurrency WebSocket servers due to its lightweight goroutine model (2KB stack vs OS threads), fast context switching, and high I/O multiplexing efficiency via `epoll`/`kqueue`.
- **WebSocket Library:** `github.com/coder/websocket` (formerly `nhooyr.io/websocket`) for zero-allocation, high-throughput WebSocket framing.
- **In-Memory Pub/Sub & Caching:** Redis 7.2+ Cluster for distributed pub/sub fan-out across multiple market data container pods.
- **Time-Series Storage:** PostgreSQL 16+ with TimescaleDB extension or ClickHouse for historical tick/candle retrieval.
- **Messaging:** `segmentio/kafka-go` consuming directly from matching engine event streams.

## Backend / Infra Touchpoints
- **Apache Kafka:** Topics `matching.trades.v1`, `matching.depth.v1`.
- **Redis 7.2:** Channels `market:depth:{isin}`, `market:ticker:{isin}`, `market:trades:{isin}`.
- **TimescaleDB / ClickHouse:** Tables `market_candles_1m`, `market_candles_1d`, `market_ticks`.
- **Flutter App (Prompt 507/508) & Web Client (Prompt 603):** Establish WSS connections to `/v1/market/stream`.

## Blockchain Interaction (permissioned Hyperledger Besu ledger with 1:1 custody backing, zero PII, QBFT)
- **Token Valuation Synchronization:** Live market prices streamed by this service directly represent the fair market value of the 1:1 backed `DigitalSecurityToken` contracts deployed on Hyperledger Besu.
- **Proof-of-Reserve Valuation Feed:** The real-time VWAP and closing price feeds generated by this service are ingested by the Proof-of-Reserve Reconciliation Service (Prompt 215) to calculate total asset under custody (AUC) valuations compared against custodian demat holdings.
- **Consensus & Transparency:** Market data is broadcast publicly and anonymously; zero user identity or PII is ever embedded in trade feeds or ticker streams.

## Step-by-Step Build Instructions (10-15 steps)
1. **Scaffold Service:** Initialize Go module `services/market-data-service` with performance flags and modular layout (`cmd/`, `internal/ws/`, `internal/aggregator/`, `internal/store/`).
2. **Define WebSocket Protocol Contracts:** Design compact JSON and binary Protobuf message schemas for client subscriptions, ticker broadcasts, depth updates, and trade feeds.
3. **Build High-Performance WebSocket Hub:** Implement connection pool manager with read/write goroutines, 30-second ping/pong keep-alive timers, and subscription maps using thread-safe synchronization (`sync.Map` or partitioned mutexes).
4. **Implement Client Subscription Router:** Parse incoming client frames (`SUBSCRIBE`, `UNSUBSCRIBE`, `PING`) and dynamically bind connections to specific symbol topics.
5. **Implement Slow Consumer Protection:** Implement bounded circular write buffers per client; if a client's network buffers exceed 2MB or latency lags by $> 5\text{s}$, gracefully drop oldest depth diffs or disconnect the client to preserve server stability.
6. **Build In-Memory L2 Order Book Assembler:** Maintain local order book state per ISIN by applying delta updates from `matching.depth.v1` and emitting full top-20 depth frames every 100ms.
7. **Build Real-Time Ticker Aggregator:** Ingest trade events to continuously compute Last Traded Price (LTP), 24-hour volume, 24-hour price high/low, and daily percentage change against previous close.
8. **Build OHLCV Candlestick Aggregation Engine:** Implement sliding-window bucket aggregator generating 1-minute, 5-minute, 15-minute, and 1-hour candles in memory with automatic rolling intervals.
9. **Implement Distributed Fan-Out via Redis:** For multi-pod horizontal scaling, publish aggregated market data to Redis Pub/Sub channels and consume in WebSocket hub instances.
10. **Implement Historical Candle Persistence:** Write completed 1-minute and 1-day candles asynchronously to TimescaleDB / ClickHouse using batch inserts.
11. **Expose gRPC Historical Data API:** Implement `MarketDataHistory` gRPC service for fetching historical OHLCV chart bars for mobile and web clients.
12. **Configure HTTP/WSS Entry Point:** Set up HTTP server with TLS termination / reverse proxy support, exposing `/v1/market/stream` for WSS upgrades.
13. **Implement Prometheus Metrics:** Instrument connection counters (`market_data_active_ws_connections`), broadcast message throughput, and channel fan-out latency histograms.
14. **Perform Scale & Load Testing:** Execute load tests simulating 50,000 concurrent WebSocket clients receiving 1,000 price ticks/sec, verifying CPU utilization $< 60\%$ and memory $< 1.5\text{GB}$.

### Historical Data Protobuf Definition (`market_data.proto`)
```protobuf
syntax = "proto3";

package growww.marketdata.v1;

option go_package = "growww/marketdata/v1;marketdatav1";

service MarketDataService {
  rpc GetCandles (GetCandlesRequest) returns (GetCandlesResponse);
  rpc GetTickerSnapshot (GetTickerSnapshotRequest) returns (GetTickerSnapshotResponse);
}

message GetCandlesRequest {
  string isin = 1;
  string interval = 2; // "1m", "5m", "15m", "1h", "1d"
  int64 from_timestamp_unix = 3;
  int64 to_timestamp_unix = 4;
  int32 limit = 5; // Max 1000
}

message CandleDto {
  int64 timestamp_unix = 1;
  string open = 2;
  string high = 3;
  string low = 4;
  string close = 5;
  string volume = 6;
}

message GetCandlesResponse {
  string isin = 1;
  string interval = 2;
  repeated CandleDto candles = 3;
}

message GetTickerSnapshotRequest {
  string isin = 1;
}

message GetTickerSnapshotResponse {
  string isin = 1;
  string ltp = 2;
  string change_percent = 3;
  string high = 4;
  string low = 5;
  string volume = 6;
  int64 timestamp_unix = 7;
}
```

## Security & Compliance Notes
- **Anonymous Public Streaming:** Market data streams contain zero user identity or individual order ownership data; only anonymized aggregated price levels and public trade executions are broadcast.
- **Connection Rate Limiting:** Enforces IP-level connection limits (maximum 10 active connections per IP) to mitigate connection exhaustion and DDoS attacks.
- **Zero PII Exposure:** Broadcast channels strictly strip internal order IDs or user account identifiers from trade feeds.

## Acceptance Criteria
- [ ] WebSocket server handles connection upgrade, keep-alive ping/pong, and subscription routing across multiple symbols.
- [ ] Level-2 order book depth frames accurately reflect matching engine state with updates broadcast every $\le 100\text{ms}$.
- [ ] In-memory candlestick engine computes multi-timeframe OHLCV bars without missing ticks or volume drift.
- [ ] Slow consumers are detected and throttled/disconnected without degrading performance for adjacent connections.
- [ ] System supports 50,000 concurrent client WebSocket connections with total memory usage $< 2\text{GB}$.
- [ ] gRPC historical candle API returns up to 1,000 chart bars in $< 10\text{ms}$.
