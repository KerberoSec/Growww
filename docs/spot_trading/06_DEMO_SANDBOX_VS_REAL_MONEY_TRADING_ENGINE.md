# Demo Sandbox vs Real-Money Spot Trading Architecture

## 1. Executive Vision & The Dual-Track Trading Model

A primary barrier preventing retail investors from entering digital asset and tokenized securities markets is the fear of immediate capital loss due to interface unfamiliarity or market volatility.

The Growww / NBSE platform implements a **Dual-Track Trading Model**:
- **Track 1: Demo / Paper Trading Mode (Testnet):** Complete, zero-risk simulation of the trading experience using virtual faucet funds, but executing against the **identical, real-world live Bitcoin and token market price**.
- **Track 2: Real-Money Trading Mode (Mainnet):** Production spot trading executing against genuine order book liquidity, settling on Hyperledger Besu Mainnet, and backed 1:1 by real custodial reserves.

## 3. Live Price Mirroring Invariant

Both Testnet and Mainnet share the identical real-time market data feed generated by `services/market-feeder` (Prompt 272):
- Evaluates redundant WebSocket streams from Binance, Coinbase, Kraken, and OKX.
- Calculates the 5-second trimmed median Fair Index Price.
- Broadcasts ticks and candlestick updates to both Demo and Real matching engines.
- **Guarantee:** A demo trader sees the exact same price movements, candlestick patterns, and volatility shifts as a real-money trader in real time.

## 4. Virtual Faucet & Portfolio Management (`services/demo-wallet-service`)

### 4.1 Initial Balance Provisioning
Upon first entering Demo Trading mode, the virtual wallet service automatically provisions:
- `10,000.00 vUSDT` (Virtual Tether USD)
- `1.00000000 vBTC` (Virtual Bitcoin)

### 4.2 One-Click Portfolio Reset
If a trader suffers losses or exhausts their virtual capital:
- User taps `"Reset Virtual Portfolio"` in settings or on the active trading banner.
- All open virtual resting limit orders are cancelled.
- Virtual balances are reset back to `10,000 vUSDT` and `1.0 vBTC`.
- Rate limit: Once every 24 hours per verified account.

## 5. Strict Zero-Cross-Contamination Safeguards

To mathematically guarantee that virtual testnet assets can never be converted into real money, and that real funds can never be routed into demo matching books:

1. **Independent Database Clusters:** Demo accounts and ledger entries exist in a physically distinct database (`nbse_demo_wallet`) with isolated user privileges.
2. **Cryptographic Environment Headers:**
   - Every API request carries `X-NBSE-Environment: TESTNET` or `MAINNET`.
   - The API Gateway validates that the user's JWT token signature is bound to that environment. A testnet token presented to a mainnet endpoint returns `403 Forbidden`.
3. **Chain ID Verification:** Testnet smart contracts reject calls if `block.chainid != 13371`. Mainnet contracts reject calls if `block.chainid != 2026`.
4. **Persistent Visual Demarcation:** The UI displays an unavoidable high-contrast Amber/Yellow banner during Demo mode, completely preventing accidental trades.
